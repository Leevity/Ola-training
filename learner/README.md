# ola-training · PC 学员端

基于现有移动 H5 的业务功能构建，使用 React 19 / TypeScript / Vite，遵循 `frontend/STYLE-GUIDE.md` 的蓝白色、浅灰蓝画布和效率优先风格。独立于移动 `frontend/` 和管理 `admin/`；真实调用 `backend/`，没有静态课程、假成绩或浏览器业务数据库。

## 启动

先在 `backend/` 运行 `npm ci`、`npm run build`、`npm start`，再在本目录运行：

```powershell
npm ci
npm run dev
```

访问 http://127.0.0.1:4181/#/home 。开发和预览代理 `/api` 至本地 4190。管理员通过 4180 管理端为企业成员开通账号、发布课程和分配任务。

首次本地演示可在后端已启动、管理端 4180 已启动时运行：

```powershell
cd backend
node scripts/setup-learner-demo.mjs
```

它只为开发库内置“林雨欣 / EMP1001”开通学员账号，随机密码保存在 `backend/data/learner-demo-credentials.txt`，不输出密码、不重置已有账号。当前工作区已完成此步骤，可以直接用该文件中的账号登录。生产账号由管理员开通。

## 数据与权限

学员端请求附带 `X-Ola-Client: learner`，使用独立 HttpOnly `ola_learner_session` Cookie；管理端继续使用 `ola_session`，同一浏览器可以保持两端不同身份。认证写请求同时传 CSRF。账号停用、企业切换与权限由后端校验。个人收藏、评价、会话与学习数据均按成员 / 企业保存。

首次启动会应用新增迁移 `002_learner_portal.sql`，创建收藏、课程评价、助手会话及消息已读表。后端 `src/portal.ts` 提供 `/api/learn/overview`、`favorites/:id`、`courses/:id/review`、`courses/:id/reviews`、`notifications/read`、`leaderboard`、`knowledge/:id/download`、`assistant/sessions` 和会话消息接口；学习考试训练沿用 `src/learning.ts`。

任务和课程使用服务端发布版本。考试答案不会包含标准答案；分数无法通过 URL 修改。到时提交以服务端保存的答案为准，网络中断时页面显示保存失败，可重试。离开答题页面前应确认“答案已保存”；关闭设备时无法保证尚未发出的答案成功保存。

## 实际服务边界

- 当前训练支持文字记录与人工评价。自动客户对话、录音上传、语音识别和自动评分未接入，不生成模拟回复或假分数。
- ola当前为关键词匹配检索：超级终端搜索课程，知识应用同时检索企业已就绪文本资料。六个应用共用企业知识范围；未独立配置知识库或连接大模型，返回的是原文摘录，不是 AI 综合回答。
- 浏览器朗读是设备能力，部分浏览器没有中文语音；界面会反馈失败，可以继续阅读。
- PDF/Office 解析与 OpenMAIC 互动课堂播放器尚未接入；这不影响文档课程、任务、文字练习与现有考试流程。
- 排行最多取当前企业 100 位启用成员，部门排行基于这些成员汇总；当前采用累计数据，没有虚构本周趋势或能力分数。
- 部分历史列表最多 200 条，课程评价及助手会话最多 100 条；大规模使用需增加服务端分页。

## 构建、测试与部署

```powershell
npm run build
npm test
npm run preview
```

默认端口固定 4181。生产静态文件为 `dist/`；hash 路由支持直接刷新。根目录 compose 已加入 learner 服务，提供本机 4181 nginx 代理。建议使用独立 HTTPS 学员域名，并设置后端 LEARNER_ORIGIN 为该域名（管理端 ADMIN_ORIGIN 保留管理域名）。生产 Cookie 为 Secure，必须通过 HTTPS 访问。Docker 与外部 PostgreSQL 部署尚未在当前环境实测。

功能测试、浏览器验收和截图见 [验收记录](VERIFICATION.md)。原移动 H5 尚未改为调用新 API，后续可复用这里的学员 API 约定。
