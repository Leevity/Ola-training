# PC 管理端建设计划

日期：2026-10-15。目标：管理员在 PC 配置课程、任务与知识内容，为后续 PC 用户端、H5 和 App 学训考提供业务入口。

## 1. 已确认需求与本轮范围

- 多企业各自管理，正式平台需服务端数据隔离。
- 现有 frontend 保留为移动 H5，App 首期嵌入 H5。
- 新增独立 PC 管理端，沿用 frontend/STYLE-GUIDE.md 的品牌和效率优先方向。
- 用户端与管理端未来共用身份、课程版本、任务分配和记录。
- OpenMAIC 作为生成、编辑、课堂能力层集成。

本轮交付计划文档和可运行 PC 管理端基础版本。采用 React + TypeScript + Vite，独立放在 admin，现有 H5 和 OpenMAIC 业务代码保持原样。

数据配置先通过 localStorage 保存，上传原文件通过 IndexedDB 保存。多企业切换及关联校验用于原型验证，**不构成服务端租户安全隔离**。本轮没有登录服务器、真实人员通知、学员同步、AI 调用、PDF/OCR 解析、自动阅卷或实际训练评分。

## 2. 角色与信息架构

企业管理员负责课程/任务/知识/组织；部门管理员未来限制在授权部门；内容作者未来只维护内容；学员使用用户端；平台运营员负责企业开通与系统能力。

当前展示企业管理员工作空间，成员角色可配置但不执行真实鉴权。七个页面：

| 路由 | 页面 | 基础操作 |
| --- | --- | --- |
| #overview | 工作台 | 企业统计、发布任务、近期课程、创建入口 |
| #courses | 课程管理 | 搜索、类型/状态筛选、分页、新建/编辑、发布、预览、归档/恢复 |
| #tasks | 任务管理 | 搜索、筛选、分页、草稿编辑、课程排序、成员选择、发布、详情、复制、归档 |
| #knowledge | 知识文件 | 上传、分类、搜索/筛选、预览、下载原文件、归档/恢复 |
| #members | 组织成员 | 添加/编辑、部门/角色配置、启用/停用、搜索、分页、导出 |
| #reports | 数据报告 | 配置与分配汇总、操作记录、任务 CSV 导出 |
| #settings | 企业设置 | 名称/简介/部门维护、当前存储与服务能力说明 |

## 3. 设计方案

视觉主张：浅灰蓝画布、白色工作面、品牌蓝主操作，使用清晰对齐和留白组织密集管理信息。

内容安排：固定侧栏 → 企业切换与当前位置 → 标题和主操作 → 数据工具栏 → 表格/工作区 → 分页；工作台突出内容配置与任务分配，不设置营销 Hero。

交互安排：导航和按钮使用轻量状态过渡，编辑弹窗使用短暂进入动画，任务步骤和课时采用可操作列表；尊重 reduced-motion。

共享品牌令牌：#246bfe / #1758d8 / #eaf2ff、主文字 #172238、次文字 #5f6f86、画布 #f4f6fa、分隔线 #e5eaf1、12px常规圆角。桌面新增侧栏、顶栏、表格、表单、弹窗和宽屏工作区；不复制手机底栏和430px壳层。主要文字14px，辅助文字不小于12px；主要按钮44px。

默认、处理、完成、空结果和异常状态按场景实现：文件上传有忙碌态；保存/发布有成功反馈；筛选有恢复入口；错误包含字段校验、文件类型/大小、存储失败、引用约束与非法路由。同步本地读取不伪造加载过程。

## 4. 课程工作包

### 基础字段

名称、简介、学习/训练/考试类型、分类、时长、封面、状态、版本号、更新时间、知识关联。

- 学习课：增删课时，配置名称、文档正文或视频链接。
- 训练课：选择人机/跟读/演讲，填写角色、目标、评价标准。
- 考试课：配置合格分数、时长和次数。题库与执行服务下一阶段实现。

草稿允许未完成内容；发布时必须满足对应类型的必填条件。视频地址限制 HTTP/HTTPS。已发布课程编辑后产生新版本号，保存草稿后不会自动重新发布。

当前版本只存当前内容及任务引用的版本摘要，没有完整历史内容快照。因此正式上线前必须新增不可变 CourseVersion、发布记录与内容资产引用，不能用当前版本号宣称已实现完整版本回溯。

## 5. 任务工作包

任务名称、说明、开始/截止日期、顺序完成配置、课程列表及顺序、成员名单、发布状态。

流程：任务信息 → 选择本企业已发布课程 → 调整顺序 → 按部门选成员 → 发布并分配。

约束：有效日期、结束不早于开始、至少一门课程、至少一名成员、不重复引用、课程已发布且同企业、成员启用且同企业。发布后保留课程版本摘要与成员ID，不原地编辑已发布任务；可复制新草稿。已发布任务引用的课程不可直接归档，需先处理任务。顺序锁定的实际执行由后续学习服务实现。

首版使用发布时固定成员名单，避免部门变动悄悄改变任务范围。是否沿用历史完成、补做和逾期规则将在业务服务阶段落定。

## 6. 知识与组织工作包

文件支持 TXT、MD、PDF、DOCX、PPTX，最大10MB；TXT/MD文本预览，其他格式仅保存原文件并标记待解析。原文件可下载；文件可归档恢复，已被有效课程关联时阻止归档。上传失败保留弹窗并提供明确错误。

成员配置姓名、员工编号、部门、角色与启用状态。同企业编号不可重复。成员停用不删除历史任务名单。企业设置按行维护部门，仍有成员的部门不能直接移除。

真实知识服务还需文件权限、解析/OCR、切分、持久索引、应用绑定、来源引用、版本和删除重建；真实成员管理还需邀请/导入、认证、角色授权和成员禁用后的会话失效。

## 7. 数据与模块结构

| 文件 | 职责 |
| --- | --- |
| src/domain.ts | 业务类型、发布校验、任务摘要、归档约束、CSV安全转义 |
| src/seed.ts | 两家企业的示例课程/任务/成员/文件 |
| src/storage.ts | 配置存储、IndexedDB文件存储、下载 |
| src/ui.tsx | 标题、状态、空态、分页、字段、可访问弹窗 |
| src/editors.tsx | 课程/任务/成员编辑器 |
| src/App.tsx | 工作空间、页面组装、动作与反馈 |
| src/styles.css | 品牌令牌与桌面/小屏布局 |
| tests/domain.test.mjs | 跨企业引用、状态约束、快照、归档、CSV等业务测试 |

保存成功后才更新内存数据，存储异常不能静默显示成功。操作记录有企业范围。上传元数据和原文件分别存储，真实后端接入时需用事务/补偿确保二者一致；本地异常可能留下无引用文件记录，当前不做自动清理。

## 8. 分阶段实施与验收

| 阶段 | 实施内容 | 验收门槛 |
| --- | --- | --- |
| A 本轮 | 计划、七页框架、配置/发布/分配、本地持久化、基础视觉和交互 | 构建通过，关键业务测试通过，浏览器完成课程→任务→成员链路 |
| B 业务服务 | 企业身份、部门/角色、数据库、文件服务、不可变版本与API契约 | 两企业对象/文件/索引不可越权，登录与禁用生效，刷新/换端一致 |
| C OpenMAIC | 可信Owner映射、生成Run、素材、编辑器、课堂、事件对账 | 真制课可恢复、结果可审核、原接口不能绕过企业准入 |
| D 任务与用户端 | PC用户端/H5接入、分配记录、完成规则、进度服务、App登录 | 管理端发布→学员学习→进度更新→管理端报告一致 |
| E 训练与考试 | 场景/量表、真实会话、题库/试卷/attempt、阅卷、知识应用 | 评价可追溯，服务端成绩确定，交卷幂等，知识引用受限 |
| F 上线 | App音频、并发、额度、监控、恢复、隔离和权限回归 | 目标环境真机和多企业验收通过 |

服务端接口按 /admin/courses、/admin/tasks、/admin/members、/admin/knowledge、/admin/reports 等业务资源规划；当前未创建这些 HTTP 接口。适配层不把客户端传来的企业ID直接视为可信身份。

## 9. OpenMAIC 接入前置条件

- 不把多个企业映射到同一共享Owner。
- 检查文档、场景、媒体、运行记录、事件流和导出的所有访问路径；只隐藏列表不够。
- 业务发布是企业/部门/成员范围发布，不能等同原有public发布。
- 生成完成先进入待审核，不自动发布给学员。
- onRunEvent 不能单独承担可靠入库：用持久映射、幂等事件和轮询对账补偿。
- 管理端可先嵌入受控编辑工作区，真实SSO不在URL暴露长期token/API Key。
- 共享实例还是每企业独立实例，由两企业授权原型验证后确定。

## 10. 验证清单

1. 构建和类型检查：npm run build。
2. 业务约束：npm test，覆盖跨企业引用、无效发布、摘要保存、引用归档和CSV公式防护。
3. 浏览器：新建并发布带课时课程、刷新恢复、切企业无同名数据、新建并发布任务、详情核对名单与版本、阻止引用归档。
4. 文件：真实本地文件上传、文本预览、原文件下载；不将待解析错误标为已解析。
5. 成员：新建、编号重复拒绝、编辑、停用与分配选项一致。
6. 视觉：桌面1440px/1280px、小屏768px/390px，检查弹窗、表格、导航与文本溢出。
7. 可访问性：弹窗语义、焦点恢复/圈定、Escape、表单标签、状态反馈、减少动画。
8. 本轮不得宣称真实多租户安全隔离、AI接入或学员同步已完成。

浏览器结果与截图索引见 design-qa.md。运行说明见 README.md。计划中的后续阶段是完整产品路线，不属于本轮基础管理端已实现功能。
